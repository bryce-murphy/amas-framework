# ADR-004 — Pre-canonical-Actions-batch insertion of linked-pr-fix-up Action

## Status

Accepted — 2026-05-03

Consumes one ADR-003 Decision 3 contingency slot (5 remaining → 4 remaining). Does not amend ADR-003; its anticipation language at Decision 3 explicitly authorizes contingency-slot consumption for substantive cycles inserted ahead of the canonical Actions batch sequence.

## Context

The PMN-001 (k) chore-fix-up cycle runs after every substantive-content PR merge, performing mechanical YAML-frontmatter substitutions: `linked_pr` squash-SHA placeholder substitution and `status: drafted` → `recorded` (PMN + canonical-content artifacts) / `status: active` → `resolved` (TASK handoffs) flips. The cycle is mechanical, repetitive, and high-volume — 10 substantive-cycle instances through PR-19 (PR-1, PR-3, PR-5, PR-7, PR-9, PR-11, PR-13, PR-15, PR-17, PR-19; per spec enumeration; Builder cross-reference at PR-21 review-context per (j) sweep discipline). Projected another 25-30 instances through canonical Actions batch ship at TASK-0023+ per ADR-003 Decision 2 PR plan.

ADR-003 Decision 2 originally placed all Actions in a single canonical batch (one of the substantive-content PRs at TASK-0023+). ADR-003 Decision 3 reserved seven contingency slots (TASK-0020 through TASK-0026) to absorb anticipated PMN insertions or substantive cycles inserted ahead of the canonical sequence. The anticipation pattern that authorizes contingency-slot consumption via subsequent ADR amendments is canonicalized at **ADR-002 Decision 3**: "subsequent ADR amendments will document such extensions following the same pattern as ADR-002"; ADR-003 preserves the pattern by reference at its Status field ("consistent with ADR-002 Decision 3 anticipation pattern"). This ADR exercises that anticipation.

Owner directive at TASK-0018 cycle close: ship the linked-pr-fix-up Action now rather than wait for the canonical Actions batch. Architect Phase 1 scoping confirmed Path X (ship as TASK-0019 substantive cycle) over Path Y (bundle into PMN-008 chore-fix-up PR-20) and Path Z (further-defer to canonical batch). The Action's own ship cycle (this cycle, PR-21) is the first production-validation event; the Action does NOT auto-fire on its own ship cycle's close — it auto-fires on PR-22 (the next substantive-content PR's close) at earliest.

## Decision

Insert the linked-pr-fix-up GitHub Action ahead of the canonical Actions batch as TASK-0019 substantive cycle. The Action lives at `.github/workflows/linked-pr-fix-up.yml` (workflow definition, ~144 lines) plus `.github/scripts/linked-pr-fix-up.py` (Python substitution script, ~158 lines), placed at canonical operational paths (NOT at the eventual `actions/<action-name>/` template-distribution layout that the canonical Actions batch will create).

**Rationale**:

1. **Manual-burden elimination**. Each PMN-001 (k) chore-fix-up currently consumes a manual cycle (ratify substitution targets, author chore-PR body, push, owner-merges via §10.5 admin bypass per ADR-001 decision 9). Shipping now eliminates that burden for all subsequent substantive cycles between this cycle and canonical-batch ship — projected ~15-25 manual-cycle savings depending on canonical-batch landing time.
2. **Empirical-track-record input to canonical batch**. The Action's operational track record between TASK-0019 ship and canonical-batch ship (recursion-guard regex behavior, idempotency under re-fire, frontmatter-substitution edge cases, failure modes if any) becomes design input for the canonical Actions batch's authoring. Pre-batch insertion buys 25-30 production-fire instances of empirical evidence the canonical batch otherwise wouldn't have.
3. **Owner directive ratification**. Per Architect Phase 1 scoping at TASK-0018 cycle close, owner adjudicated Path X (ship now) ratified. Path Y (bundle into PMN-008 chore-fix-up PR-20) was rejected because it mixes mechanical and substantive scope, breaks the chore-fix-up cycle's mechanical-only invariant, and complicates the §24.3.1 five-point post-handback check at PR-20 close. Path Z (further-defer to canonical batch) was rejected because it accumulates 3-5 more manual chore-fix-up cycles unnecessarily and wastes the owner-readiness signal.

**Recursion-guard refinement**. The §E1 recursion-guard regex `^chore/task-[0-9]+-(linked-pr-fix-up|pmn-001-k)$` (anchored, alternation between auto-generated chore-fix-up shape and manual fallback shape) replaced an earlier substring-match form `*linked-pr-fix-up*` || `*pmn-001-k*` at Phase 1 scoping. The substring-match form would have triggered the recursion guard against the Action's own parent feature branch `feat/task-0019-linked-pr-fix-up-action` (because that branch contains the substring `linked-pr-fix-up`), suppressing the Action's first auto-fire on PR-22. The anchored form correctly differentiates the recursive cases (`chore/task-NNNN-...`) from the non-recursive parent feature branch.

## Alternatives considered

**Path Y — Bundle into PMN-008 chore-fix-up (PR-20)**. The TASK-0018 PMN-001 (k) chore-fix-up PR (PR-20) could have absorbed the linked-pr-fix-up Action authoring as a sidecar deliverable. Rejected because (i) mixes mechanical (chore-fix-up substitutions) and substantive (Action authoring + ADR-004) scope in a single PR, contrary to the project's one-artifact-class-per-PR convention; (ii) breaks the chore-fix-up cycle's mechanical-only invariant — chore-fix-up cycles are non-substantive by design (mechanical YAML-frontmatter substitutions only); (iii) complicates the §24.3.1 five-point post-handback check by mixing post-merge mechanical-substitution evidence with substantive-content evidence.

**Path Z — Defer to canonical Actions batch (TASK-0023+)**. The Action could have shipped as part of the canonical Actions batch alongside the other 9 enumerated workflows per ADR-003 Decision 2 PR plan. Rejected because (i) owner-readiness signal at TASK-0018 cycle close indicates ship-now intent; (ii) deferral accumulates 3-5 more manual chore-fix-up cycles between now and canonical-batch ship, each consuming owner attention unnecessarily; (iii) the Action's pre-batch operational track record is empirical input the canonical batch benefits from receiving.

## Consequences

1. **Operational source-of-truth at `.github/`** until canonical Actions batch migration. The Action lives at `.github/workflows/linked-pr-fix-up.yml` + `.github/scripts/linked-pr-fix-up.py` (operational layout) until the canonical Actions batch (anticipated TASK-0023+) creates the canonical `actions/<action-name>/` source layout with both template and operational expressions. Migration from operational to canonical layout happens at canonical batch cycle, not this cycle.
2. **Canonical Actions batch design-input.** The canonical Actions batch authoring (anticipated TASK-0023+) inherits this Action's empirical operational track record as input — recursion-guard patterns, idempotency under re-fire, frontmatter-substitution edge cases, failure modes if any. The 25-30 production-fire instances between this cycle and canonical-batch ship are empirical evidence the canonical batch otherwise wouldn't have.
3. **ADR-003 Decision 3 contingency slots: 5 → 4 remaining** post-this-decision per spec accounting (Architect Phase 1 scoping). Specific TASK-slot enumeration of remaining contingency reserves is per-cycle-tracked at handoff metadata; the spec count claim stands as the cycle-close ledger entry. Future PMN insertions or substantive cycles inserted ahead of the canonical sequence consume from this remaining-4-slot reserve per the ADR-002 Decision 3 anticipation pattern.
4. **github-reference.md §6.2 Actions enumeration update deferred**. github-reference.md (PR-17 / TASK-0017 substantive content) currently enumerates 9 Actions per ADR-003 Decision 2 PR plan. The Action enumeration in github-reference.md grows from 9 to 10 entries with this cycle's insertion; that update is deferred to the canonical Actions batch cycle (not modified at this cycle to keep TASK-0019 scope tight to Action authoring + ADR-004).
5. **README.md Action enumeration not modified this cycle.** Existing "Actions (9 workflows)" subsection enumerates `actions/<name>.yml` template-distribution paths shipped at PR-15. The linked-pr-fix-up Action lives at `.github/workflows/linked-pr-fix-up.yml` (operational dogfood path), structurally distinct from the template-distribution layer. README enumeration of operational dogfood Actions deferred to canonical Actions batch cycle, which will create the canonical `actions/<action-name>/` source layout with both template and operational expressions. See ADR-003 D3 contingency-slot consumption (5 → 4).
6. **README.md line 9 canonical-version-of-record bump** v2.17 → v2.18 applied this cycle per §18.4 substantive-reading minor criterion (substantive new functional content via the Action + new architectural decision via this ADR). Class A surgical edit (TWO `v2.17` → `v2.18` instances on line 9); Class B/C historical/dated cross-document state in core.md and CLAUDE.md preserved verbatim.
7. **Pre-canonical-batch insertion precedent**. This decision sets a precedent that future Actions MAY ship pre-batch under similar conditions (owner directive + clear high-volume mechanical cycle being automated + empirical-track-record-input rationale). Future similar decisions reference this ADR as precedent.
